# TG Workbench

面向本地运营的 Telegram 群组、频道与话题镜像工作台。后端、管理 API 和 Web UI 打包成一个 Windows EXE，默认只监听 `127.0.0.1:8765`。

## 快速开始

1. 双击 `dist/TGWorkbench.exe`。
2. 浏览器打开 `http://127.0.0.1:8765`。
3. 在“Telegram 账号”中填写从 `my.telegram.org` 获得的 API ID、API Hash 和手机号。
4. 点击连接，在页面中提交 Telegram 验证码；账号启用两步验证时继续提交密码。
5. 登录后创建线路，从同步的对话列表选择来源和目标，也可手工填写 `-100...` Chat ID 与话题 ID。
6. 在线路上添加按序执行的内容规则，并用实时预览验证结果。

建议使用独立服务账号，不要使用承载个人隐私和资金操作的主账号。

## 已实现

- 多 Telegram 用户账号、加密 session、断线后的会话恢复
- 多来源到多目标、论坛话题匹配与目标话题发送
- 文本和说明文字的普通替换、正则替换、用户名/链接替换、前后缀
- 命中丢弃、命中审核、全量审核、审核改稿、手工插入消息
- 照片、视频、文件、语音、贴纸、联系人、位置、骰子的原样转发或无来源复制
- 相册按 `grouped_id` 聚合后整组发送
- 来源编辑和删除同步，持久化来源到目标的消息 ID 映射
- 账号对话同步、状态监控、操作日志和 Windows 自动启动
- SOCKS5 Telegram 代理
- 本地 Host 校验、安全响应头、1 MB API 请求限制
- API Hash 和 Telegram session 使用 AES-GCM；主密钥由 Windows DPAPI 绑定到当前用户

## 明确限制

- Telegram 标记为受保护的内容不会被绕过或复制。
- 投票、实时位置、付费内容和部分服务消息在复制模式下进入审核；原样转发模式由 Telegram 决定能否发送。
- 审核队列当前只保存可编辑文本；批准特殊媒体审核项时会发送文本，不会重建投票或实时位置。
- 反应同步字段已预留，但当前不自动复制 reaction。
- 对话选择器当前读取最近 100 个对话，较旧会话可手工填写 Chat ID。
- 规则改写后以纯文本实体发送，原消息中的粗体、链接实体可能被重建为普通文本。

## 构建

在 PowerShell 中运行：

```powershell
.\build.ps1
```

脚本会构建 Web UI、运行全部 Go 测试，并生成 `dist\TGWorkbench.exe`。上游 `uTLS 1.8.2` 的 Windows 发布包遗漏源码文件，因此 `go.mod` 固定到已修复该问题的上游提交 `880e27d8b0e5`，并使用包含安全修复的 Go 1.25.12 构建。

默认数据目录是 `%LOCALAPPDATA%\TGWorkbench`。可用 `-data` 指定测试目录，用 `-listen` 指定另一个本机回环端口。

## 运营建议

- 先用测试群验证每条线路，确认账号有来源读取权和目标发送权。
- 广告、联系方式、价格、收款信息建议配置 `review_if`，不要只做盲目替换。
- 同一来源不要配置相互回流的线路。工作台会忽略自己发出的更新，但无法判断其他机器人重新包装后的同内容消息。
- 关注 Telegram Flood Wait。当前运行时逐目标顺序发送并记录错误，不会为规避平台限制而并发轰炸。
